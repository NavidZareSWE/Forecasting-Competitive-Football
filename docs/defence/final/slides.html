Model 3 — Task L

→ updated distribution and updated margin
Reference · its own frozen pre-match prediction

28,823 rows \(= 1{,}517 \times 19\)

Why RPS: the outcomes are ordered — predicting a home win and getting a draw is a smaller error than getting an away win. Accuracy cannot express that; log loss treats both mistakes as equal. Log loss, Brier and ECE are reported alongside it.

We do not mark our own homework: every classification number is reported against the de-vigged bookmaker market on identical matches. The constant prior is the floor.

05 · leakage 1:30

Four barriers, each enforced by code

The label is derivable from the same event stream the features come from. So the leakage rules are not prose in a report — they are assertions and unit tests.

  • 1 · Chronological split — 896 / 277 / 344 by date; every snapshot inherits its match's side; grouped CV inside training
  • 2 · Prior-match-only form — one-match lag before the 5-game window. The strong test: rewrite a match's own scoreline and assert its feature row is byte-identical
  • 3 · The time-t cut — see right; guarded on both sides
  • 4 · Train-only transforms — imputer, scaler, encoder, resampler fit on training rows only; the pipeline raises if resampling is requested on the snapshot table
TRAIN · 896
VAL · 277
TEST · 344
effective_minute = np.maximum.accumulate(minute) sort by (period, index) — never by timestamp 
minute     0   3   7   9  10  ⚠0  12  14   ← corrupted row
effective  0   3   7   9  10  10  12  14   ← pinned, not dragged

A running maximum never decreases, so effective_minute[i] ≤ t implies the true minute is also \(\le t\) — the repair can only make the cut more conservative, never less.

Two-sided guard: last included event \(\le t\) and first excluded event strictly \(> t\) — a too-aggressive cut would weaken the model invisibly.

07 · the papers 1:15

Two papers, and why these two

P1 · G-SMOTENC

Fonseca & Bacao · ESWA 234 · 2023 · Q1 Scimago
✓ year ✓ venue ✓ applicable ✓ non-deep

Targets the actual imperfection in our data: draws are the minority class (~26.5%) and the table mixes nominal + continuous. Generates inside a geometric region, and produces nominal values by mode over the selected neighbours — never a fractional one-hot that corresponds to no real category.

src/papers/g_smotenc.py · 8 tests

P2 · Hierarchical Shrinkage

Agarwal et al. · ICML 2022 · CORE A*
✓ year ✓ venue ✓ applicable ✓ non-deep

Leaves the tree structure untouched, rewrites only the node values: each split's increment is damped in proportion to how little data supported it — one parameter λ. Applies unchanged to classification and regression, so one method serves Models 1, 2 and 3.

9 tests · equation checked on every root-to-leaf path

\[ \hat{f}(x) = \bar{y}_{\text{root}} + \sum_{\text{splits}} \Delta_{s} \big/ \left(1 + \lambda / N(\text{parent}_{s})\right) \] \(\lambda \to 0\) recovers the tree exactly · \(\lambda \to \infty\) collapses to the root mean — both asserted

The reversal: FIGS ranked first initially; we switched to Hierarchical Shrinkage because its core is one closed-form transformation — no iterative optimiser, no unstated constants — which made the hand derivation and line-by-line fidelity tests possible. Sign-off at Mid Defence 2.

Declared deviations, not hidden ones: P2 — base learner is a scikit-learn forest (the paper applies HS to standard fitted ensembles); one λ by CV, to keep the equal-budget protocol honest. P1 — Algorithm 1 extended binary → multiclass · deterministic tie-break in the mode · truncation / deformation fixed at 1.0 / 0.5.

08 · the protocol 0:50

How the comparison was made fair

Equal budget

12 candidates per model per task · random search · 3-fold CV inside training rows only, grouped by match on Task L. The equality is asserted at the end of the run, not merely described.

Calibration

Isotonic on the validation split with the base estimator frozen — the calibrator can neither refit the model nor see test rows.

One licensed test

Match-clustered bootstrap + Holm–Bonferroni within each task. 19 snapshots of one match are not 19 observations — a row-level bootstrap understates variance by ~the cluster size. Seed repetition is a stability diagnostic only.

TRAINfits models · hosts internal CV
VALIDATIONcalibrators · links · every ablation
TESTread exactly once

Was the budget enough? Best-vs-median CV gap on Task C: GBM 0.45271 · LightGBM 0.19134 · XGBoost 0.16004 — against random forest 0.00839 · kernel SVM 0.02138 · P2 0.00343. Boosted models genuinely needed the search; low-variance models were already near their best.

TreeSHAP is exact for tree ensembles and additive: contributions for one prediction sum to (prediction − average output) — every explanation is checkable.

  • Pre-match led by away_venue_form_xga — mean |SHAP| 0.022888 (C) · 0.147635 (R): venue-split defensive form, then the venue-split difference
  • In-play led by the score state — inplay_diff_goals 0.056485 (Lc) · inplay_goal_diff 0.244491 (Lr) — it displaces every pre-match feature
  • Ablation agrees independently: deleting the current-score group costs +0.04964 RPS (Lc) · +0.26796 MAE (Lr) on validation — an order of magnitude beyond any other group
Self-critical point, made unprompted
SHAP shows the model uses the features football knowledge says it should — which rules out fitting an artefact. It does not show the model is good: pre-match proves a model can use the right features and still not beat the base rate.

14 · results — the imbalance study 0:45

P1: the result the paper predicts, and the one it does not

Six arms on the pre-match table · mean draw recall vs mean RPS per arm · resampling_study.csv

Detection and probability quality are different objectives: the arm that finds the most draws is last on RPS (P1, recall 0.14874), while the best-scoring arm is mid-pack on recall (SMOTE, 0.21893). The two rankings are not the same.

P1 isolated on validation: draw recall rises on 2 of 2 learners tested — random forest 0.0769 → 0.3462, xgboost 0.1282 → 0.2949 — and RPS improves on 0 of 2. Exactly what the definitions predict: a proper scoring rule is minimised by the true class probabilities (\(\approx \tfrac{1}{4}\) for draws), and rebalancing pushes the predicted draw rate above it.

The conclusion is a product decision: calibrated probabilities → leave P1 off; flagging likely draws (a real draw-market requirement) → rebalancing works, and P1 delivers the largest recall gains per learner. The snapshot table is excluded by design — the pipeline raises if any arm touches it: interpolating across matches builds states of no possible game and leaks labels.

16 · hardening 1:00

Five quieter defects — and what each left behind

tuning.py passed use_p1= to a parameter named resampling=
Crashed in 1.4 s — every earlier number was library defaults. Fixed, whole search re-run. Left behind: best_params.json now checkpoints per task with automatic resume — an interruption no longer discards hours. A fast crash is the good version of this bug.
xG joined on team name, not team_id
away_xg = 0.0 for Marseille and Caen — spellings differ across StatsBomb file families. Caught because one away goal with zero xG is impossible, not just unlikely. Left behind: every join uses identifiers, never spellings.
SimpleImputer silently dropped all-empty columns
Would have misaligned every SHAP name against the design matrix — attributions labelled with the wrong feature. Left behind: keep_empty_features=True.
Nyström requested more landmarks than fold rows
Some search candidates were scored under a configuration that was not the one requested. Left behind: a ClampedNystroem wrapper caps components at fold size.
The snapshot ablation thinned validation as well as training
Each arm scored on a different set of minutes — a coarser grid could win by being scored on easier minutes. Left behind: only training rows are thinned, and the evaluation column exists to keep that invariant visible.

The dangerous version of a bug runs to completion and hands you plausible numbers. Each fix above became a permanent guard — none of these five can happen twice.

17 · conclusions 1:00

What we know, what we do not, and what we would do next

Demonstrated
Live information beats every modelling choice: 0.21862 → 0.02266 RPS from kick-off to minute 90 — and the in-play result is statistically supported (6/15 · 9/15 survive Holm); the pre-match leaderboard is not (0/21 on C; the 6/36 on R are all against the constant baseline). Both papers reimplemented from scratch and verified against their published equations (8 + 9 tests).
Tested — and refuted, twice
The snapshot grid: training on 7 snapshots per match (63% fewer rows, evaluation grid fixed) scores 0.12815 vs 0.12902 — not worse; adjacent snapshots are near-duplicates, effective sample size is matches, not rows. The overfitting suspicion: 231 columns on 896 rows looked thin, so we rebuilt the whole pipeline at 75 columns — wide wins the point estimate on all 4 tasks and 21 of 24 learners, 0 of 24 survive Holm. The prediction was specific, and it was wrong.
Limitations, named plainly
One season, four leagues — and a real 43.3% → 48.6% home-win drift induced by the chronological split · no squad-quality or team-news features — the largest component of the market gap · 277 validation matches is thin for isotonic, so calibration sometimes worsens ECE · feature groups overlap heavily, so the ablation has limited power to separate them · no in-play market exists to judge Model 3 against.
Next steps — each tied to a finding
Squad-strength features from the (built, unused) lineup store → attacks the measured +0.02213 market gap · per-phase calibrator for Model 3 → slide 12 measured the global one mis-specified at both ends · further seasons → the one specific cure for the split-induced drift, enabling a whole-season hold-out.

A null result at 344 test matches is a statement about detectable effects at this sample size — not a demonstration of equivalence. Since no learner separates from another pre-match, the constraint is the information, not model capacity — which tells the client exactly where to spend next.

Why kernels are Nyström-only at snapshot scale — measured, not assumed

Fit seconds vs training rows · log–log · kernel_scaling.csv

Empirical exponents: exact kernel ridge \(n^{2.291}\) · exact SVR \(n^{1.938}\) · Nyström \(n^{0.281}\). At 17,024 snapshots the exact Gram matrix alone is 2,211 MB; exact ridge fits in 114.98 s at up to 4,450 MB peak, Nyström in 0.411 s at 138 MB — a factor of 280 in time. And Nyström costs 0.004 MAE pre-match where both fit (slide 9).
